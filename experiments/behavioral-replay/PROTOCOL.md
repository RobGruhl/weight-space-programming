# Bounded behavioral portability experiment

Frozen before new generation, 2026-11-07. This is a small local development experiment, not reproduction of upstream's 32,768-token vLLM benchmarks or independent discovery of an edit. No private mail, external inference, API spending, training, or production changes. Own adapter only; upstream code is not executed.

## Design

Use the four exact synthetic prompts from the earlier smoke as development, never fresh holdout. Three arms: unchanged baseline, exact published p50c, and one row-permuted p50c delta control. Generation seed 0 reset per sample; control seeds 20261107 and 20261108 for manifest tensor indices 0 and 1 fixed before outcomes. The control independently permutes residual-output rows within each edited tensor, using the same row permutation across its 64 selected columns. This preserves the unrounded delta's singular values and column norms but disrupts its alignment with residual coordinates. It tests direction specificity conditional on the published choice of columns, not whether those columns were discovered independently. After BF16 rounding, report actual norm, changed support, cosine with p50c, and hash; fail preparation if relative norm mismatch exceeds 1%. No direction or seed search and no norm tuning using outcomes. The published alpha=6 edit reverses the selected directional projection to approximately −5 times its original value; it is not orthogonal removal to zero.

The control uses the union of changed columns, including every row in those columns (65,536 selected entries per tensor), not the sparse archive's post-rounding nonzero support. Actual changed entries can differ between arms after BF16 rounding. No entries outside these columns may change. A single random control cannot establish a random-control distribution.

Pair identical rendered inputs, source precision, tokenizer, decoding and seed. Order is fixed by prompt: baseline/p50c/shuffled, p50c/shuffled/baseline, shuffled/baseline/p50c, baseline/p50c/shuffled. Restore base tensors before each arm; hash all state tensors after each arm installation. All other parameters must stay byte-identical. Do not overwrite the checkpoint or historical reports.

Thinking enabled, temperature 0.6, top-p 0.95, top-k 20, generated-token presence penalty 1.5, maximum 8192 new tokens. Stop only for EOS, token limit, 210 seconds elapsed, or memory safety (process RSS >12 GiB, MPS driver allocation >14 GiB). Check between tokens; these are approximate limits, not hard real-time guarantees. A 2700-second whole-run limit stops further samples and preserves the partial result. External watchdog may interrupt a hung process, with streamed tokens and attempt/error records retained. Expected upper token workload 98,304 tokens, roughly 35 minutes at prior 47 tokens/second; 12 per-sample time caps total 42 minutes plus setup. No model is loaded until GPU release is explicitly granted by the operator.

## Outcomes and retention

Repetition is diagnostic only and never a stop criterion: record any four consecutive identical 16-token blocks, their first ending token index, plus maximum adjacent repeated-block run. Capping does not imply looping. Preserve all generated tokens, rendered prompts, prompt IDs, exact text, EOS IDs, actual EOS versus cutoff, closed-thinking marker, last box and exact string match. For EOS completions with a nonempty box after the closing thinking marker, grade the four integer answers by exact final-box match; boxes inside thinking are extraction diagnostics only. Track answer-format compliance separately; manually review the complete final answer if alternative formatting creates ambiguity, recording that review separately. Missing completed answers remain a separate missing-answer category. Censored samples have semantic correctness null even if an intermediate box matches. Do not pool missing answers, wrong answers, repetitions and cutoffs into one score.

Every attempt has a unique directory, immutable executed code/protocol snapshots and hashes, full source/patch hashes, runtime versions, start/end/error records, streamed tokens, per-sample resource telemetry, and final result. MPS memory reports are sampled current allocator/driver bytes, not a guaranteed device peak or total unified-memory usage; RSS is a process lifetime peak. Keep every failed or interrupted attempt. No reruns selected for nicer results.
